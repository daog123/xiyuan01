# 第四轮：FFN word读取与自动Q/K/V链

日期：2026-10-26。工程E:/speed-up；主顶层llm_graph_top，ABI v5。当前改动保留在工作区，未提交或推送。所有性能行均为实际RTL仿真，物理结果为10ns内部OOC，不是板级或完整模型结果。

本轮完成FFN向量DMA的对齐word读取，以及一次提交的K/V投影、量化、事务式KV追加、Q投影和Attention。计算阵列仍复用原4×4；没有扩大MAC通道。完整回归、K4096整链及当前物理实现均通过。

## 1. 结构与完成边界

新opcode QKV_ATTENTION=6锁存三份bounded投影任务、attention描述符及token，根ID为attention.task_id。流程为：

```text
整图预检 → K投影/写确认 → K动态量化/缓存
         → V投影/写确认 → V动态量化/缓存
         → KV_APPEND(K,V,SK,SV) → 全部B确认及长度提交
         → Q投影/写确认 → Q动态量化 → Attention → Y写确认 → 根完成
```

K/V顺序复用一个Q16.16动态量化器，缓存两条INT8向量和group scales，主机不喂K/V或Q数据流。原opcode0..5在握手当拍直接进入已有引擎，避免为旧任务再复制一份大描述符或增加发射周期。

三份投影必须M1、N=dimension、K相同，子ID互异。整个计划的维度、格式、地址、stride、容量和跨投影/持久KV别名在访存前检查。三份投影复用一个检查器，别名检查按槽位遍历。只有先验证M1、N≤64、K≤4096，才缩窄检查器几何操作数；K8192、N129、高位地址溢出等负例全部要求零AXI访问。

KV已有配置；每个请求只追加一个head的一个新token，attention.tokens=token+1。实际追加位置由KV管理器检查是否等于已提交长度；Q只在追加提交后启动。原有INT8/Q16.16 Attention和手动KV接口保留。

### 提交后失败可恢复，但整图不回滚

根完成保留stage：0预检，8/9 K投影/量化，10/11 V投影/量化，12追加，13表示本次KV追加已提交并进入Q/Attention。stage8..12失败不会启动Q；追加失败不增加已提交长度，但临时区或未提交字节可以部分改变。stage13失败时不能直接重放完整append，可在错误原因解除后只执行Q_ATTENTION。

软件Completion新增可选stage，TaskExecutionError保留completion；QKVAttentionPlan.kv_committed(event)判断本次是否越过提交确认点，无stage失败记录返回None。False不代表缓存里不存在同一个token。plan.resume_query()产生仅Q/Attention计划，库不自动重试。transport须在完成有效、ACK之前采样ID/status/elapsed/stage。接口详见qkv_attention.md。

数值仍沿用原W4A8、group UQ4.12、Q16.16舍入/饱和和Attention合同；动态量化scale=clamp(ceil(absmax/2032),1,65535)。没有引入RoPE或改变Softmax定义。

## 2. FFN实测收益

gate/up每个Q16.16输入从4个字节读事务合为1个对齐4字节事务。每个中间元素共减少6个读事务，读取有效字节仍为8字节。SiLU/SwiGLU、动态量化、qx/sx写确认和down发射条件不变，仍是单拍、单outstanding。

配对实验只替换ffn_dma；基线为冻结的tb/baselines/ffn_dma_round3.sv，计算核、当前调度、数据和内存服务相同。读延迟0/8/24、写延迟4以及group12补充配置，共12组FFN和12组LINEAR对照、48个完整外存任务。每任务逐字节比较65,536字节；有效读取字节、写入与B确认相同。

## 3. 较大规模整链实测
