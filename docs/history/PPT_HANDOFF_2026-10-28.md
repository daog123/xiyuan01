## 4. 工程结构及已实现范围

当前主顶层 `llm_graph_top`，ABI v5。生产默认 4×4 阵列、TILE_K32、group32，64 位 AXI 数据和地址。一个活动任务，阶段顺序执行，统一管理完成与错误恢复。

| 模块 | 已实现/已验证的内容 | 范围 |
| --- | --- | --- |
| LINEAR | signed INT4 权重 × INT8 激活，INT32 分组部分和，sx/sw 合并、舍入与饱和，Q16.16 输出 | 默认 M/N≤64、K≤4096 |
| FFN | gate/up → 中间结果真实读取 → SiLU/SwiGLU → 动态量化 → 写确认 → down | H≤64，中间元素≤512 |
| KV | K/V/scale 平面，按 layer/head 的元数据，追加、读、清空和提交长度 | 有界缓存；无完整多层模型调度 |
| Attention | QK → 近似 Softmax → AV → 写回 | 单 query、指定单 head，D≤64、可见前缀≤16 |
| 自动子链 | K/V 投影与量化 → KV 追加 → Q 投影与量化 → Attention | 单 head、单新 token，有提交后恢复机制 |
| 供数 | 有界连续读、短 burst、权重行窗口、激活尺度缓存，保留背压、错误排空和写确认 | 尚未实现充分搬运/计算重叠或多 outstanding |

完整 Transformer Block、真实模型运行、O 投影、RoPE、RMSNorm、残差、稀疏选择及模型质量评估仍需继续。原文献中的研究方向不能当作已经实现的算法贡献。

## 5. 可使用的内部优化数据

### 第五轮：形状映射（计算核层面）

按 M 调整 M/K 映射，复用小 M 时空闲的 PE 行。64 逻辑乘积通道、8×8 研究核、N64/K4096 的配对核心实验中，M2 加速约 2.172×、M4 约 1.926×；默认 4×4 的 M2 约 1.898×。该轮完整外存算子收益较小，提示供数成为瓶颈。详见 `compute_round5.md`，不要把 8×8 研究配置说成默认生产配置。

### 第六至第七轮：供数优化（完整算子 RTL 仿真）

R6 增加有界短 burst 与返回缓冲。R7 在此基础上增加两个 16 字节权重行窗口，以及同 M/ml/group 的 sx 缓存，改善小请求和重复读取。

- 相对 R6，8 组长 LINEAR 加速 **1.90165–2.14307×**。
- 12 组小 LINEAR 加速 1.14138–1.66706×；12 组小 FFN 加速 1.08705–1.45475×。
- 相同数学任务、数值格式、阵列和 AXI 服务条件，计时包括装载、计算、后处理、外存写入与 B 确认。
- 两项缓存均关闭时，32 组周期与流量复现 R6；单项消融、完整内存及错误探针通过。

建议展示的代表例：4×4、M8/N64/K4096、group32，固定读延迟 8 拍、写延迟 4 拍：

| 完整 LINEAR 周期 | 1,152,380 | 537,724 |
| AR 请求数 | 87,040 | 22,528 |
| 权重读取有效字节 | 262,144 | 262,144 |

## 8. 距离完整上板和完整模型还缺什么

最近目标：主机写入 A/W/sx/sw → 提交任务 → 自研完整 LINEAR 从真实存储取数 → FPGA 完成数值后处理与写回 → 主机读回全部 Y 并逐项核对。

关键缺口是计算侧可修改 shell，或重建它所需的准确资料：DDR 器件/组织/管脚及 IP；Aurora/GT/参考时钟和 AXI 连接；时钟、复位、ready 和跨时钟处理；地址译码；约束及工具版本。现有驱动包反复深挖后仍未找到完整计算侧工程。可以自行写工程，但不能猜测板卡连线。

不依赖这些资料的可选下一步是用片上 BRAM 接入完整 LINEAR，先验证完整后处理与读写路径。它仍不等于主机动态输入或真实 DDR 数据通路。

完整模型还需 O/RoPE/RMSNorm/残差/完整 Block、模型导出和权重、跨层执行及容量、真实模型质量与吞吐评估。
