# 第三轮：自动Q链路与有界连续读取

工程：E:/speed-up。ABI v4；默认主系统4×4/TILE_K32/GROUP_SIZE32。下文均为当前源码实际仿真或OOC实现，未提交、未推送。MAC按一次数学乘积累加计数。

本轮完成两项：一次提交Q投影→动态量化→Attention；将矩阵/Q读取从逐字节gather改为有界连续1/2/4/8字节读取。长K主系统存储路径实测加速3.75–3.81倍，完整系统回归与10ns内部时序通过。

## 1. 结构推进到哪里

新增opcode `Q_ATTENTION=5`，同时锁存linear_task和attention_task，软件封装为ProjectedAttentionPlan。仅复用现有计算阵列，顺序执行：

```text
形状/分配区检查 → LINEAR Q投影 → 全部B确认
               → Q16.16读取 → 完整group动态INT8/UQ4.12量化
               → Attention读取已提交KV → Y写回及B确认 → 根completion
```

根ID为attention_task.task_id，中间投影成功不对主机暴露completion。M=1、N=dimension，单head；Q源字段新增2，Q16.16须4字节对齐、容量至少4×dimension，scale地址/容量为0。普通ATTENTION也支持Q16.16输入。原INT8主机流和内存INT8/scale入口保留。

Q临时区和最终Y均不得覆盖持久KV；最终Y也不得覆盖仍存活的投影输入，Q/Y不得重叠。投影写确认前不允许Q读取。投影失败停止Attention；后续失败不回滚Q临时区或部分Y写入，result_available为0。tokens是否超过已提交前缀仍由Attention阶段检查，图不是原子事务。

量化复用原requant_dynamic/group：`scale=clamp(ceil(absmax/2032),1,65535)`；Q按Q16.16/(16×scale)最近舍入、半数远离零，最终INT8饱和。完整group确定scale后输出，尾group按真实长度处理；零group scale=1。整数数值合同和Softmax定义不变。

当前K/V仍须事先配置并append。K/V投影、自动append、RoPE、O投影、RMSNorm/残差和完整Block尚未完成。本轮完成M1中的Q子链，未把M1整阶段勾选完成。详细接口及复现见projected_attention.md。

## 2. 性能改在哪里，收益有多大

旧packet每个字节分别经历命令/响应/填槽。新packet按当前W行、A行、scale片段给出合法连续上限，新读取器选择满足自然对齐且不越上限的最大1/2/4/8字节，一次填多个槽。跨行、尾字节、stride padding和两列打包孔洞分开处理，不向下对齐或预读额外字节。Q输入同样使用该读取器。

这是ARLEN=0、单outstanding的单拍读取；没有宣称已经实现burst或多请求并行。FFN向量阶段的旧字节读取仍保留。

### 长K：实际主系统4×4存储路径

两版使用相同当前计算核、调度、数据、64位总线和内存服务，仅替换packet/bridge逐字节基线。GROUP_SIZE32、TILE_K32；固定读延迟8、写延迟4；从空缓存开始，计算到最终写确认后完成。每个任务检查全部262,144字节外存镜像；有效读取字节、写入数和B确认数逐项相等。基线冻结源码位于tb/baselines/*_round2.sv。

### 与上一轮计算微基准分开理解

第二轮的9.64 MAC/拍（4×4长单行）使用核接口连续8字节供数；本轮长单行0.519 MAC/拍包含真实packet/AXI服务和写确认。不能将它们当作同一边界，也不能将本轮3.81倍直接乘到上游计算核对照里。

当前长单行平均有效存储读取约0.308字节/拍，8行约0.307字节/拍。单在途事务、请求/返回间隔和packet调度仍限制供数；算术核心并未在本轮增加乘积通道。下一步应优先改善供数，而非继续增加乘法器。
