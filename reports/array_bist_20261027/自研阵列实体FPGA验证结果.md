# 自研脉动阵列实体 FPGA 最小验证结果

2026 年 10 月 27 日，当前项目的 **4×4 自研脉动计算阵列已在实体 FPGA 上完成固定数据计算验证**。8 组用例的 128 项板内逐项比较全部一致，实际输出滚动校验值为 `0x1f41`；故意改错一项预期结果的独立对照准确报告 1 项错误。主机收到 3 个正常结果帧、2 个故障对照帧，CRC 全部正确。

本轮采用项目现有的 `w4a8_compute_array` 和 `mac_pe` 计算代码，计算源码保持原样，新增 ROM 输入、启动控制、预期值比较及结果回传电路。此前使用参考矩阵核验证项目数值的结果仍有效；本轮新增自研阵列实体运行证据。

## 数据与验证范围

使用有符号 INT8 激活和 INT4 权重，权重符号扩展至 8 位送入现有 PE，INT32 累加。配置 `vector_mode=0`、`BROADCAST_MAC=0`、`PACKED_MAC=0`，验证输出驻留脉动模式。预期值由 Python 独立整数点积生成，种子 20261027。

| 用例 | M×N×K | 内容 |
| --- | --- | --- |
| 0 | 4×4×32 | 确定性随机数据 |
| 1 | 4×4×31 | INT8/INT4 正负边界值 |
| 2 | 3×2×17 | 随机数据与尾块 |
| 3 | 1×4×1 | 单步点积与边界值 |
| 4 | 2×3×8 | 全零输入 |
| 5 | 4×4×16 | 规律递增数据 |
| 6 | 4×4×32 | 正负边界值 |
| 7 | 4×4×37 | 超过 tile K=32 的长度 |

共 96 个有效计算输出，另有 32 项检查无效位置为零，合计 128 项；有效乘加数 2,522。控制电路插入暂停，检查暂停后的数据推进。全部输入、预期矩阵和形状保存于 `repro/vectors.json`。

## 最小工程

```mermaid
flowchart LR
    A[固定输入 ROM] --> B[项目现有 4×4 脉动阵列]
    B --> C[逐项比较与实际输出校验值]
    D[Python 预期 ROM] --> C
    C --> E[带 CRC 的结果帧]
    E --> F[专用 DONE 信号]
    F --> G[C6 管理接口与主机解码]
```

使用 STARTUPE3 内部振荡器，经 BUFGCE_DIV 除以 8，名义频率约 6.25 MHz。普通引脚端口数为 0，计算输入固定在 ROM，本轮不依赖计算侧 DDR、Aurora 或外部时钟管脚约束。启动后经专用 DONE 信号回传动态帧；静态 DONE 高电平不能通过解码验收。

**主机读取的是校验值、错误数和状态帧。128 个原始累加器值在 FPGA 内与预期 ROM 逐项比较，未逐项传回主机。** 正常逐项比较、实际输出校验值和独立故障对照共同构成本轮正确性证据。

## 本轮修复

1. 修正器件型号。成功参考镜像使用 `xcvu9p_CIV-flgb2104-2-i`、IDCODE `0x04b35093`；此前标准型号镜像使用 `0x04b31093`，两次加载均未完成。改用 Vivado 正式 CIV 目标重建后，诊断和阵列镜像均完成实体加载。没有手工篡改配置 ID 或关闭 CRC。
2. 明确启动阶段 DONE 状态，同步配置结束信号并显式初始化回传寄存器，启动时保持 DONE 高，随后发送动态帧。
3. 保留 C6 文件头兼容处理：配置数据偏移规范化到 128 字节，配置数据逐字节不变，并保存独立哈希。此前仅对齐文件头未解决标准型号加载失败。
4. 加载前同时检查 CIV 文件头和配置 ID，错误型号会在打开硬件节点前被拒绝。仅操作固定 PCI `0000:84:00.0`、chipsel=1。
5. 修正 `config/board_endpoint_profile.json` 和三个板级打包/验证脚本的目标型号，保存修改前备份。完整 LINEAR 端点的实体接入状态仍为未完成。

阵列测试镜像实现资源：2,014 LUT、881 个寄存器、32 DSP、0 BRAM、0 普通绑定 I/O。保守时钟约束下 setup WNS=123.774 ns、hold WHS=0.027 ns，时序通过，设计规则检查 0 错误。资源数包含两份阵列和测试电路，不直接代表单份生产阵列资源或性能。
