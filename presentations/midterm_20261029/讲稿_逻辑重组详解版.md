# 曦源项目讲稿：逻辑重组详解版

对应V8第1—9页。本版展开因果关系与技术解释，供理解和修改；3分钟上台稿另见同目录《讲稿_逻辑重组3分钟版.md》。第7—9页沿用上一版。

## 第1页：研究背景与问题

各位老师好，我们的项目是面向边缘场景的高效大语言模型推理硬件加速。相较于服务器，边缘设备的存储容量、计算能力和内存带宽更有限，这使大模型部署面临三个相互关联的问题。

首先，模型权重规模大，推理过程中还会产生大量激活数据，容易超出边缘设备的存储和带宽承受能力。因此需要通过低比特量化等方法压缩数据，但压缩会引入数值误差，所以还必须研究如何保持模型质量。

其次，在长轮次对话中，随着累计token数增加，KV缓存的存储量近似线性增长，生成每个新token时需要访问的历史信息也越来越多。因此，我们希望研究稀疏注意力和选择性KV访问，减少对当前生成贡献较小的计算与数据读取。

最后，软件层面减少了数据量或运算量，并不意味着硬件一定更快。压缩格式的解码、数据搬运、任务映射和控制都可能抵消收益。因此，第三个问题是：如何让算法和编码设计与实际硬件结构配合，将理论节省转化为实际执行收益。

## 第2页：前期调研与设计依据

根据刚才的三个问题，我们分别开展了相关调研。

在压缩与精度方面，SmoothQuant通过等价变换，将激活离群值带来的量化难度转移到更容易量化的权重侧，以支持W8A8计算；KIVI则根据K、V的分布差异采用不同量化维度，为KV缓存压缩提供了参考。

在注意力访问方面，PQCache利用乘积量化近似检索重要token，再读取对应KV进行计算；FlashAttention通过分块和片上复用减少数据搬运。这些工作分别启发我们考虑“哪些历史信息需要访问”和“需要访问的数据如何更高效地搬运”。

在硬件实现方面，FlightLLM研究了矩阵、向量计算模式及并行度配置；FlashAttention-2强调改善任务划分和降低非矩阵运算开销；DSP-Packing进一步提供了低位宽多乘积打包与符号误差修正的参考。这些认识对应到后续的映射、结果处理和资源复用设计。

## 第3页：总体架构与本阶段实现

基于这些调研，我们规划了从主机任务到硬件执行的整体流程。完整推理中，文字首先转换为token和数值向量，主机再把计算任务和数据交给硬件。

统一任务控制负责安排算子顺序，AXI读写和缓存负责提供权重、激活及量化尺度；W4A8矩阵核完成投影和FFN中的矩阵乘法，数值后处理负责恢复尺度、累加、舍入和饱和。Attention结合当前查询和历史KV提取上下文，FFN进一步变换特征。

在完整模型中，这些计算配合Norm、RoPE和残差连接，经过多层处理后，通过词表投影得到下一个token的分数，选取token，再由主机解码成文字，并继续下一步生成。本阶段已完成图中低比特计算、后处理及有界算子链，后续逐步打通完整生成流程。

围绕这条执行链，我们重点优化了结果交付、计算映射和低比特资源利用三个环节。

## 第4页：部分和缓存分bank与并行后处理

先看计算结果能否及时保存和处理。原实现将部分和逐个写入单写端口缓冲区，再由单路尺度处理单元依次缩放和累加。这种组织的优点是地址和控制简单，便于逐项验证，但阵列已经并行算出结果后，保存和后处理仍然串行，形成了瓶颈。

结合调研中降低非矩阵处理和数据交换开销的思路，我们将部分和缓冲区改为按列分bank，一拍保存一行结果，再用双路后处理并行恢复量化尺度。

这样，8乘8满块的保存时间由64拍降到8拍。在M8、N64、K4096的配对实验中，计算核周期由127007拍降到68966拍，加速约1.84倍。

## 第5页：形状感知的M/K并行重映射

解决结果交付后，我们进一步看阵列是否被充分利用。原映射主要让物理PE行对应输出矩阵的行。当有效行数较少时，一部分PE行会闲置；原核虽然已有M等于1的向量路径，但M等于2、4及尾块仍有优化空间。

FlightLLM关于M、K、N并行度配置的讨论，为这种形状适配提供了参考。我们根据有效行数，将空闲PE行用于K维分片计算，并同步调整激活、权重路由和归约子树，将属于同一逻辑输出、同一量化组的部分和合并，再进入尺度处理。

在M等于2的代表任务中，周期从47627拍降到21929拍，加速约2.17倍。

## 第6页：两个低比特乘积共享DSP

在提升阵列利用率之外，我们还希望提高每个DSP的利用率。原实现中，每路乘积独立使用乘法资源，便于保持各路累加独立，但INT8乘INT4没有用满DSP乘法器的位宽。

参考DSP-Packing所讨论的共享操作数打包及误差修正方法，我们将两个权重错位打包，与同一个激活相乘，再拆出两路乘积，并修正低位负乘积对高位的影响，分别送入独立累加器。

在8乘8广播配置下，DSP从74个降到42个，减少43.2%，计算周期保持相同。

## 第7页：开源计算核对比

我们也进行了开源计算核的受控对比。在统一64路逻辑乘积通道和供数预算、计入冷加载与后处理后，代表性单行任务中，本工程使用9510拍，略低于openTPU的9564拍。多行任务仍有进一步优化空间。

## 第8页：实现进度与FPGA原型

目前，LINEAR、FFN、KV、有界Attention及自动QKV子链已经完成RTL验证。我们也将自研脉动阵列运行在实体FPGA上，完成固定输入的功能验证，并正在推进主机动态输入与完整LINEAR外存数据通路的接入。

## 文献要点：用于理解和备答

| 工作 | 主要思想与关键设计 | 与本项目的联系 |
|---|---|---|
| [SmoothQuant](https://arxiv.org/abs/2211.10438) | 通过等价的通道缩放平滑激活离群值，将量化难度转移到权重侧，支持W8A8 | 为后续模型校准与精度保持提供参考；本工程当前格式为W4A8 |
| [KIVI](https://arxiv.org/html/2402.02750v2) | K按通道、V按token量化，结合分组低精度缓存和高精度残留部分，支持流式追加 | KV压缩及量化维度的后续研究依据 |
| [PQCache](https://arxiv.org/html/2407.12820v2) | 用乘积量化编码和码本近似检索重要token，再读取对应KV；结合缓存和通信重叠 | 重要token选择和选择性KV访问的后续方向 |
| [FlashAttention](https://arxiv.org/abs/2205.14135) | IO感知分块与片上复用，减少中间矩阵在外存中的读写，标准版本保持精确稠密注意力 | 说明减少数据搬运也能提速；选择性访问主要对应PQCache，不能将FlashAttention本身称为稀疏化方法 |
| [FlashAttention-2](https://arxiv.org/abs/2307.08691) | 减少非矩阵运算，改善跨线程块与warp内的工作划分，减少共享存储通信 | 为优化一提供“并行计算之外还应优化结果处理与通信”的原则联系；分bank与双路后处理是本工程的具体实现 |
| [FlightLLM](https://arxiv.org/html/2401.03868v2) | 可配置稀疏DSP链、统一矩阵引擎、矩阵/向量模式及并行度分析，并结合片上Decode与编译映射 | 对应总体架构、形状适配及优化二；本工程具体实现为PE行重映射、操作数路由和组内归约 |
| [DSP-Packing](https://arxiv.org/html/2203.11028v1) | 推广多乘积打包到不同位宽，分析符号与结果提取误差，并讨论精确修正及近似过度打包 | 优化三采用精确乘积提取与修正的路线；该论文为补充参考 |

以上联系按技术内容整理。FA2提供的是设计原则上的联系；DSP-Packing为补充核对的参考，不据此倒推实际开发前的阅读顺序。

## 第3页的模块解释：从输入文字到屏幕上的回复

| 步骤 | 做什么 | 当前图中的对应位置 |
|---|---|---|
| 分词与Embedding | 将输入文字转为token编号，再查表得到向量 | 完整流程的主机/模型前端，当前硬件图主要从数值任务入口开始 |
| 主机提交任务 | 说明算什么、形状多大、数据在哪里 | 主机任务接口、统一任务控制 |
| 读取与分块 | 搬运权重、激活、尺度，按阵列可处理的块供数 | AXI读写、分块供数与缓存 |
| 低比特矩阵计算 | 以4位权重和8位激活进行点积与累加，用于Q/K/V投影及FFN投影 | W4A8矩阵核 |
| 数值后处理 | 按量化组乘回尺度、合并结果，进行舍入和饱和；下一算子需要时再量化 | 数值后处理、动态量化 |
| Attention | Q表示当前查询，K用于计算相关性，V提供被加权汇合的内容；历史K/V由缓存保存 | 独立的有界Attention/KV引擎，当前QK/AV并未统一到W4A8阵列 |
| FFN | 通过投影、SiLU/SwiGLU等非线性和后续投影变换特征 | 矩阵核与FFN/动态量化模块配合 |
| 完整层与多层执行 | 配合Norm、RoPE、残差等，按模型结构反复执行各层 | 部分算子已实现，完整Block与整模型调度仍需补齐 |
| 词表投影与选token | 将最后的隐藏向量投影成词表分数，再用贪心或采样选出下一个token | 完整生成流程的模型输出端，当前尚未打通 |
| 文字解码与循环 | 主机将token序列解码成文字，并继续生成，直到结束条件满足 | 最终用户界面；它不同于硬件中的Decode推理阶段 |

KV缓存量在固定模型结构、批量和缓存策略下随保留token数近似线性增长；普通Decode中单个新token的注意力工作量随历史长度增加。完整稠密Prefill的注意力工作量则随输入长度呈二次增长。这里以累计token数描述上下文长度，比直接按对话轮数计量更准确。
