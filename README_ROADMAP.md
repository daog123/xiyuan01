### 当前明确限制

| 项目 | 当前范围 |
|---|---|
| Attention | 默认每次单 query，最大可见前缀 16 token、维度 64；最大 layers=4、heads=8；可见范围由调用方选择，且不得超出 KV 已提交长度 |
| Q 输入 | signed INT8 流与重复的逐组 UQ4.12 scale；自动投影到 Q 流尚未接通 |
| 线性任务 | 默认 max M=64、N=64、K=4096；阵列 4×4；group size=32 |
| FFN | 默认 H≤64，M×H≤512；共享计算核的 group size 为编译配置 |
| 外存接口 | 窄单拍、单 outstanding AXI；不是高带宽 DDR 数据通路 |
| 未完成运算图 | 完整 Q/K/V/O 自动链、RMSNorm、RoPE、残差、多层模型与 token 生成 |
| 板级 | 器件配置暂为 xcvu9p-flga2104-2L-e，实际板卡未确认；DDR/PCIe、CDC、引脚和 I/O 约束尚未接齐 |

当前是统一算子系统，尚不是完整 Transformer 或可直接上板运行的 LLM 系统。上述限制必须由实际实现与验证逐项解除。

## 2. 长期目标与系统边界

长期目标：在 FPGA 板卡上运行选定的真实量化模型，支持 prefill 和逐 token decode，完成连续文本生成，并报告准确性、容量、延迟、吞吐、资源和功耗。

第一版可由主机承担分词、请求管理、采样和文本输出，FPGA 承担 Transformer 层的主要计算。Embedding、最终投影等放在哪一端需在目标模型确定后明确记录；主机参与的部分也属于端到端系统边界，不能省略。

暂不同时承诺多个模型、任意长度上下文或所有 Attention 变体。先锁定一个目标模型结构、一种量化配置和一块板卡，再依据需求扩展。

## 3. 阶段任务与验收

阶段按依赖推进，不预设没有依据的完成日期。板级准备可与计算图开发并行。

### M0：固定接口和数值规范

- [ ] 确定目标模型结构、层数、hidden/head/FFN 维度、head 数与 KV head 数。
- [ ] 明确 norm 位置与 epsilon、RoPE 参数/维度布局、Q/K 的 RoPE 与量化顺序、W4 布局、分组尺度和零值处理。
- [ ] 统一各阶段输入/输出格式、舍入/饱和规则、张量布局、buffer 生命周期、完成条件和错误语义。
- [ ] 建立固定随机种子的小尺寸参考、逐阶段输出与误差度量；真实模型未确定时可先做合成配置。
- [ ] 建立板卡信息表：器件完整料号、DDR 类型/容量、主机接口、现有控制器工程、时钟/复位和约束文件。

交付：接口/数值说明、参考配置、固定输入与软件参考。验收：所有成员可以独立生成一致的输入和阶段结果。

### M1：自动 Q/K/V → Attention → O 链路（下一轮首要任务）

- [ ] 用一次图请求描述 Q/K/V/O 的矩阵任务、量化、KV 操作与缓冲区；明确图级任务 ID、子任务和状态。
- [ ] 自动执行 Q/K/V 投影及所需量化与写回。
- [ ] 增加 Q DMA/流转换，从外存读取投影结果并正确产生 scale 和 last。
- [ ] K/V append 确认完成后才允许 Attention 读取；Attention Y 写确认后才允许 O 投影。
- [ ] 检查整图形状、地址、容量和不安全的别名；对运行时错误停止后续阶段并处理已发出的事务。
- [ ] 将该链路纳入统一运行入口、配置、源码清单与日志。

交付：现有小尺寸下自动运行的投影/Attention 链。验收：一次提交完成全链，无须主机手工喂 Q 或在阶段间搬运数据；各阶段对照整数参考；覆盖延迟响应、读写错误、连续任务、复位恢复与 ID 路由。M1 本身尚不是完整 Block。

### M2：完整小尺寸 Transformer Block

- [ ] 实现 RMSNorm、RoPE、残差模块及软件参考，按 M0 固定的位置与数据格式接入。
- [ ] 将 M1 链路与既有 FFN 连接，管理两次残差所需的原始输入和中间结果。
- [ ] 支持小尺寸多 token prefill 与逐 token decode，明确位置、可见前缀与 KV 长度的更新。
- [ ] 保留各阶段结果，定位整数差异和近似运算误差。

交付：一次请求自动完成单层 Block。验收：完整层输入到输出可复现；整数路径符合整数参考；采用同一数学定义和因果范围的 prefill/decode 对照满足预设容差；旧算子回归继续通过。

### M3：真实模型尺寸与多层执行

- [ ] 建立真实权重/层输入导出与校准流程，记录模型来源、版本和允许的使用方式。
- [ ] 将 M/N 分块调度纳入运行时，自动管理权重、scale、输出及尾块。
- [ ] 若目标 K 超限，增加跨 K 块的原始高精度累加和最终一次舍入；不能直接相加各块已舍入的 Q16.16 输出。
- [ ] 改造 FFN 按行/组流式处理，解除整块 M×H 缓存限制；动态量化的 absmax 必须覆盖完整量化组。
- [ ] 依据模型需要扩展 Attention 维度、上下文与 KV 存储；需要时实现 GQA 映射、分页或其他 mask，不同时无条件扩展所有变体。
- [ ] 完成多层权重、每层 KV、临时空间与依赖管理；接齐模型其余部分及主机生成循环。

交付：真实单层后推进多层/完整目标模型。验收：报告实际支持形状与内存占用，完成真实权重比较及连续生成。截取真实模型部分维度仅算局部测试，不算完整模型运行。

### M4：板级 DDR 与主机接口闭环

- [ ] 接入实际 DDR 控制器和地址映射；在真实接口上保持现有完成/fence 语义。
- [ ] 接入选定主机接口与控制寄存器/描述符通路，完成数据装载、启动、查询、错误和回读。
- [ ] 补齐 CDC、复位、引脚、时钟和外部 I/O 约束，并为失去响应的 fabric 制定平台恢复机制。
- [ ] 依次执行 DDR 读写、LINEAR、FFN、Attention、Block 和模型测试。

交付：可复现的板级工程、主机运行方式与实测记录。验收：实际目标器件完整实现和时序检查通过；板上输入/输出符合参考；连续运行与异常恢复通过。OOC 结果不能替代板级验收。

### M5：性能优化与可复现发布

- [ ] 增加阶段周期、等待周期、字节量和错误计数，定位计算/带宽瓶颈。
- [ ] 根据测量增加 AXI burst、多 outstanding、FIFO、预取/双缓冲和阶段重叠，重新验证顺序、反压与 fence。
- [ ] 在带宽支持下优化阵列、存储复用和并行度；必要时再扩展并发与批处理。
- [ ] 固定模型、量化方式、序列长度和硬件配置，发布可重复的性能与精度结果。

交付：优化版本、基线对照和复现说明。验收：旧/新结果符合数值合同，并同时给出首 token 延迟、decode token/s、有效带宽、资源、时序及实测功耗（具备测量条件时）。仿真周期估算与板级实测分别标注。

## 5. 验证基线与复现入口

实现基线 `af1f0a6` 的本地记录包括 19 个软件单元测试、8 组系统 RTL 配置、141 条完成记录、3,211,264 字节完整内存比较，以及原有 7 类兼容套件。该记录用于说明已有覆盖范围，不等于新环境已完成回归。

同一基线的 VU9P、10 ns 内部时钟 OOC 布局布线记录为 WNS +0.321 ns、WHS +0.010 ns，56,725 条可路由网络全部完成、路由错误 0。实际板卡尚未确认，这些结果不是板级 DDR/PCIe 或真实模型验证。

从项目根目录执行：

```powershell
python .\scripts\project.py test
python .\scripts\project.py implement
python .\scripts\project.py status
python .\scripts\project.py legacy
```

依赖与路径设置见[项目 README](README.md)。`test` 重新生成参考数据；`status` 核验当前实现输入与证据的关联。完整回归和布局布线耗时较长，每个阶段需按改动选择检查；仅修改规划文档无需重新声称完成硬件验证。

`build/`、`.Xil/`、日志、Python 缓存及原始 `xiyuan_BF` 目录/压缩包按现有规则留在本地。仓库包含有效源码、测试、脚本、配置与文档，新环境须重新生成构建产物。
